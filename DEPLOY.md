# Бот на сервере: круглосуточно, без твоего компьютера

Итог: бот живёт на VPS, стартует сам после перезагрузки сервера, поднимается
после падений, база знаний бэкапится каждую ночь. Компьютер можно выключать.

Занимает 20–30 минут, из них половина — ожидание письма от хостера.

---

## Прежде чем начать: два токена под замену

Папка проекта приехала с чужого компьютера (в `.venv` был прописан путь
`C:\Users\diman\...`). Значит `BOT_TOKEN` и `AI_API_KEY` видел кто-то ещё, и
дальше они поедут на сервер. Перевыпусти оба — это две минуты:

- **Токен бота**: [@BotFather](https://t.me/BotFather) → `/mybots` → твой бот →
  *API Token* → *Revoke current token*. Старый перестанет работать сразу.
- **Ключ AnyModel**: личный кабинет → удалить старый ключ, создать новый.

Новые значения впишешь в `.env` на сервере (шаг 4). В `.env.example` реальные
значения лучше не возвращать — это файл-шаблон, он ходит вместе с проектом.

---

## 1. Взять VPS

Подойдёт самый дешёвый тариф: боту хватает 1 ядра и 1 ГБ памяти.

**Важно — датацентр за пределами России.** Нидерланды, Германия, Финляндия.
Оттуда `api.telegram.org` и AnyModel открываются напрямую, и вся возня с VPN,
прокси и SOCKS, которая была нужна на твоём компьютере, просто исчезает. На
российском хостинге придётся тащить туда ещё и прокси — не надо.

Ориентиры по цене: Hetzner CX22 (~€4), Aeza, PQ.Hosting, VDSina — 200–400 ₽/мес.

При заказе выбери:

- ОС: **Ubuntu 24.04 LTS**
- вход по SSH-ключу, если умеешь; если нет — по паролю, хостер пришлёт его на почту

На выходе у тебя будет IP-адрес и пароль root.

## 2. Зайти на сервер

Windows 10/11, обычный `cmd` или PowerShell:

```
ssh root@ВАШ_IP
```

Первый раз спросит `Are you sure you want to continue connecting?` — ответь `yes`.
Пароль при вводе не отображается, это нормально.

## 3. Залить файлы проекта

Проще всего [WinSCP](https://winscp.net): протокол SFTP, хост — IP сервера,
пользователь `root`, пароль от хостера. Слева твоя папка `tgbot sh`, справа
сервер. Создай справа папку `/opt/kb-bot` и перетащи в неё **всё, кроме**:

- `.venv` — окружение сервера создаст себе сам (и оно всё равно непереносимо)
- `knowledge.db*` — если хочешь начать с чистой базы; хочешь перенести
  накопленное — копируй все три файла `knowledge.db`, `-wal`, `-shm` вместе
- `wheels`, `start.bat`, `check_ai.bat` — это для Windows

Через терминал то же самое одной командой (запускать в папке проекта на
компьютере, не на сервере):

```
scp -r bot.py ai.py db.py config.py md.py net.py test_search.py requirements.txt README.md .env.example deploy root@ВАШ_IP:/opt/kb-bot/
```

## 4. Установить

На сервере:

```bash
bash /opt/kb-bot/deploy/install.sh
```

Скрипт поставит Python и sqlite3, заведёт отдельного пользователя `kbbot`,
соберёт виртуальное окружение, положит systemd-юниты и включит ночной бэкап.
В конце попросит вписать токены:

```bash
nano /opt/kb-bot/.env
```

Обязательные строки — `BOT_TOKEN`, `ADMIN_IDS`, `AI_API_KEY`. Всё, что про
прокси (`TELEGRAM_PROXY`, `AI_PROXY`), оставь **пустым**: на зарубежном сервере
прямое соединение работает, и бот это определит сам.

Сохранить в nano: `Ctrl+O`, `Enter`, потом `Ctrl+X`.

## 5. Запустить

```bash
systemctl enable --now kb-bot
journalctl -u kb-bot -f
```

В логе должно появиться:

```
INFO net: https://api.telegram.org: доступен напрямую
INFO bot: Сеть: Telegram напрямую | ИИ напрямую
INFO bot: Бот запущен: @твой_бот
```

Выйти из просмотра логов — `Ctrl+C` (бот при этом продолжает работать).

> **Останови бота на своём компьютере.** Два процесса с одним токеном
> одновременно работать не могут: Telegram отдаёт апдейты только одному, второй
> будет валиться с `Conflict: terminated by other getUpdates request`.

Теперь напиши боту в Telegram. Отвечает — готово, компьютер можно выключать.

## Каждый день

| Что нужно | Команда |
|---|---|
| Работает ли | `systemctl status kb-bot` |
| Смотреть логи вживую | `journalctl -u kb-bot -f` |
| Что было за сутки | `journalctl -u kb-bot --since today` |
| Перезапустить | `systemctl restart kb-bot` |
| Остановить | `systemctl stop kb-bot` |
| Список бэкапов | `ls -lh /opt/kb-bot/backups` |
| Сделать бэкап сейчас | `sudo -u kbbot /opt/kb-bot/deploy/backup.sh` |
| Когда следующий бэкап | `systemctl list-timers kb-bot-backup` |

## Обновить код

Закинул новые `.py` в `/opt/kb-bot` (WinSCP или `scp`) — и:

```bash
bash /opt/kb-bot/deploy/update.sh
```

Скрипт сам сделает бэкап базы, доставит зависимости, поправит права и
перезапустит сервис. `.env` и `knowledge.db` он не трогает.

## Забрать базу знаний себе

```
scp root@ВАШ_IP:/opt/kb-bot/backups/knowledge_*.db.gz .
```

Или прямо из бота: `/export` — пришлёт CSV в Telegram.

## Если что-то не так

**Сервис не стартует.** `journalctl -u kb-bot -n 50` покажет причину. Чаще
всего это опечатка в `.env` или незаполненный `BOT_TOKEN`.

**`Conflict: terminated by other getUpdates request`** — где-то запущен второй
экземпляр с тем же токеном. Обычно это бот на твоём компьютере: закрой окно
`start.bat`.

**Бот перезапускается по кругу.** Смотри `journalctl -u kb-bot -n 100`. Если
там `Нет доступа к api.telegram.org` — хостинг всё-таки в России или у
провайдера блокировки; проще сменить датацентр, чем настраивать прокси.

**Кончилось место.** `df -h`. Логи journald чистятся так:

```bash
journalctl --vacuum-size=200M
```

**Хочу вернуть базу из бэкапа:**

```bash
systemctl stop kb-bot
cd /opt/kb-bot
mv knowledge.db knowledge.db.old
gunzip -c backups/knowledge_2026-01-15_0430.db.gz > knowledge.db
chown kbbot:kbbot knowledge.db
systemctl start kb-bot
```

## Что где лежит

```
/opt/kb-bot/
├── .env                 токены и настройки (права 600, только kbbot)
├── knowledge.db         база знаний
├── backups/             ночные снимки, хранятся 14 дней
├── .venv/               окружение Python
├── bot.py ...           код
└── deploy/
    ├── install.sh       первичная установка
    ├── update.sh        обновление кода
    ├── backup.sh        снимок базы
    ├── kb-bot.service   сам сервис
    └── kb-bot-backup.*  ночной бэкап (сервис + таймер)
```

Бот работает под отдельным пользователем `kbbot` без прав root и, кроме своей
папки, писать никуда не может — если в коде что-то сломается, остальной сервер
это не заденет.

## Сколько это стоит в работе

VPS — фиксированная абонентка. Запросы к ИИ — по токенам AnyModel, и тут
работает база: один раз спрошенное больше в модель не уходит. Переспрос (см.
README) стоит копейки по сравнению с генерацией ответа. Следить за расходом —
командой `/stats`: она показывает, сколько запросов пришло и сколько из них
ушло в ИИ.
