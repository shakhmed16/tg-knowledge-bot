# Telegram-бот с базой знаний и ИИ

Логика на каждый вопрос пользователя:

1. **Поиск в базе** (SQLite): точное совпадение → FTS5 по ключевым словам → нечёткое
   сравнение → эмбеддинги (если включены). Скоры смешиваются в один рейтинг.
2. Если лучший результат ≥ `MATCH_THRESHOLD` — бот отвечает **из базы**.
3. Если результат в «серой зоне» (`RERANK_MIN_SCORE`..`MATCH_THRESHOLD`) — бот
   **переспрашивает дешёвую модель**: показывает ей 3 кандидата и спрашивает,
   отвечает ли какой-то из них на вопрос. Да → ответ из базы, нет → шаг 4.
   Это заменяет эмбеддинги, которых у AnyModel нет (см. «Смысловой поиск»).
4. Иначе — запрос уходит в **ИИ** (AnyModel), причём топ-3 близкие записи из базы
   передаются модели как контекст.
5. Ответ ИИ **сразу сохраняется в базу** (`source='ai'`) и в следующий раз выдаётся
   уже без обращения к модели. Под ответом кнопки 👍/👎 — 👎 удаляет запись,
   чтобы в базе не копился мусор. Разговорные реплики («привет», «как тебя
   зовут») и уклончивые ответы («зависит от…», «точно не скажу») в базу
   не попадают.


## Настройка `.env`

- `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather).
- `ADMIN_IDS` — ваш Telegram ID (узнать: [@userinfobot](https://t.me/userinfobot)),
  несколько — через запятую.
- `AI_BASE_URL` — `https://anymodel.org/v1`.
- `AI_API_KEY` — ключ из личного кабинета AnyModel.
- `AI_MODEL` — ID модели **точно как в списке моделей AnyModel** (идентификаторы
  чувствительны к регистру, например `kmc/k3`).
- `AI_EMBEDDING_MODEL` — модель эмбеддингов. **У AnyModel их нет** (проверено:
  среди 87 моделей ни одной с `embed`), оставьте пустым. Смысловой поиск делает
  переспрос — см. ниже.
- `AI_RERANK` — включить переспрос (по умолчанию `true`).
- `AI_RERANK_MODEL` — дешёвая быстрая модель для переспроса
  (`ag/gemini-3.7-flash-low`). Если её нет у провайдера, бот подберёт другую.
- `RERANK_MIN_SCORE` — нижняя граница серой зоны (`0.25`). Ниже неё бот даже не
  переспрашивает: запрос точно про другое.
- `MATCH_THRESHOLD` — порог уверенности (по умолчанию `0.55`). Выше порог — чаще
  идём в ИИ и тратим токены; ниже — чаще отвечаем из базы, но рискуем выдать
  нерелевантную запись. Подбирается командой `/find`.

## Команды администратора

```
/add вопрос | ответ     добавить запись вручную
/del <id>               удалить запись
/find <текст>           показать, что найдёт бот, со скорами (для настройки порога)
/list [ai|manual|import] последние 20 записей
/leads                  последние заявки на осмотр
/audit                  найти услуги с разными ценами в разных записях
/stats                  статистика базы и обращений к ИИ
/export                 выгрузка базы в CSV
/reindex                досчитать эмбеддинги для записей без векторов
```

Импорт: просто пришлите боту CSV-файл с колонками `question;answer`
(разделитель `;` или `,`, кодировка UTF-8) — см. `example_import.csv`.

## Как наполнять базу

- Импортом CSV — самый быстрый старт.
- Командой `/add` — точечно.
- Автоматически: всё, что отвечает ИИ, оседает в базе.

Если у одного и того же вопроса встречаются разные формулировки, добавьте вторую
запись с тем же ответом (`/add как вернуть покупку | <тот же текст>`) — поиск по
ключевым словам плохо связывает разные корни («возврат» и «вернуть»), а
эмбеддинги эту проблему снимают.

## База данных

SQLite-файл `knowledge.db` создаётся рядом с ботом при первом запуске.

- `qa` — вопрос, ответ, источник (`manual` / `ai` / `import`), счётчик показов;
- `qa_fts` — полнотекстовый индекс FTS5;
- `embeddings` — векторы (если включены);
- `query_log` — все запросы пользователей: что спросили, что нашли, ушло ли в ИИ.
  Полезно, чтобы видеть, каких ответов в базе не хватает.

## Проблемы при установке

**`ERROR: Could not install packages due to an OSError: Missing dependencies for SOCKS support`**

В системе задана переменная окружения `ALL_PROXY` / `HTTPS_PROXY` со SOCKS-прокси
(обычно от VPN), а у pip нет пакета PySocks. `start.bat` теперь сбрасывает
proxy-переменные на время установки — просто запустите его ещё раз.

Если ставите вручную, сделайте то же самое в своём окне cmd:

```bat
set "ALL_PROXY="
set "HTTPS_PROXY="
set "HTTP_PROXY="
.venv\Scripts\activate
python -m pip install -r requirements.txt
```

Если интернет у вас идёт **только** через этот SOCKS-прокси, поставьте поддержку
SOCKS для pip: `python -m pip install pysocks` (при отключённых proxy-переменных),
после чего установка через прокси заработает.

**`ModuleNotFoundError: No module named 'aiogram'`**

Зависимости не установились (см. пункт выше) либо запущен системный Python вместо
venv. Проверьте:

```bat
.venv\Scripts\activate
python -m pip show aiogram
```

Если папка `.venv` осталась после неудачной установки — её можно удалить и
запустить `start.bat` заново.

**Прокси и сам бот.** `httpx` подхватывает `ALL_PROXY`/`HTTPS_PROXY` из окружения,
поэтому в зависимости стоит `httpx[socks]` — запросы к AnyModel и Telegram пройдут
и через SOCKS-прокси. Если прокси не нужен, ничего делать не надо.

### Если pip упорно пишет про SOCKS

Значит прокси прописан не только в переменных окружения, но и в конфиге pip
(`%APPDATA%\pip\pip.ini`). `start.bat` теперь ставит пакеты с флагом `--isolated`,
который игнорирует и переменные окружения, и pip.ini. Вручную это выглядит так:

```bat
.venv\Scripts\python.exe -m pip install --isolated -r requirements.txt
```

Посмотреть, откуда берётся прокси:

```bat
.venv\Scripts\python.exe -m pip config list
```

Убрать его из конфига навсегда: `python -m pip config unset global.proxy`.

Если интернет доступен **только** через SOCKS-прокси, поставьте PySocks и верните
прокси: `python -m pip install --isolated pysocks`, дальше обычный
`pip install -r requirements.txt` заработает (`start.bat` пробует этот сценарий
автоматически, если прямая установка не прошла).

**`did not find executable at 'C:\Users\<чужое имя>\...\python.exe'`**

Папка `.venv` приехала вместе с проектом с другого компьютера. Внутри неё
записан путь к питону того компьютера, поэтому не работает ни `pip`, ни запуск
бота — и сообщение про SOCKS/прокси тут ни при чём. `start.bat` теперь проверяет
окружение запуском (а не наличием файла) и пересоздаёт его сам. Достаточно
запустить `start.bat` ещё раз.

Вручную:

```bat
rmdir /s /q .venv
start.bat
```

Не копируйте папку `.venv` между компьютерами — она непереносима. При переносе
проекта берите только исходники, окружение создаётся заново за полминуты.

### Python 3.14 и сборка зависимостей

Если pip начнёт собирать `pydantic-core` из исходников и упадёт с ошибкой про Rust
или компилятор — значит для вашей версии Python ещё нет готовых колёс. Самое
быстрое решение: поставить Python 3.12 или 3.13 и пересоздать окружение:

```bat
rmdir /s /q .venv
py -3.12 -m venv .venv
start.bat
```

(На Python 3.14 колёса уже есть, пересоздавать окружение под 3.12 не нужно.)

### Прокси задан в настройках Windows

Если `pip config list` и переменные окружения пусты, а ошибка про SOCKS остаётся —
прокси прописан в системных настройках Windows (Параметры → Сеть и Интернет →
Прокси-сервер), их читает сам Python через реестр, и флаг `--isolated` тут не
помогает. Решение — научить pip работать с SOCKS: в папке `wheels\` лежит
PySocks, он ставится офлайн, без сети:

```bat
.venv\Scripts\python.exe -m pip install --isolated --no-index --find-links wheels PySocks
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`start.bat` делает это автоматически. Альтернатива — временно выключить прокси в
настройках Windows, поставить зависимости и включить обратно.

## Сеть: Telegram и ИИ через VPN/прокси

Бот сам разбирается, как выйти в интернет, — настраивать ничего не нужно:

1. если в `.env` задан `TELEGRAM_PROXY` / `AI_PROXY` — используется он;
2. иначе проверяется прямое соединение (подходит, когда VPN работает в режиме
   туннеля, например Happ в TUN-режиме);
3. иначе берётся прокси из настроек Windows (Параметры → Сеть и Интернет →
   Прокси-сервер) — туда его прописывают многие VPN-клиенты;
4. иначе сканируются локальные порты популярных клиентов (Happ, v2rayN, Nekoray,
   Hiddify, Clash, Tor) и проверяется каждый — реальным запросом к Telegram.

Telegram и ИИ проверяются отдельно: если AnyModel открывается напрямую, запросы к
нему пойдут в обход прокси.

Если ни один путь не сработал, бот не падает: пишет в лог, что доступа нет, и
повторяет попытку через 10, 20, 40… секунд (максимум раз в 5 минут). Достаточно
включить VPN — бот подхватит соединение сам, перезапускать его не нужно. Так же он
переживает обрывы связи во время работы.

В логе при старте видно выбранный маршрут:

```
INFO net: https://api.telegram.org: работает через найденный прокси socks5://127.0.0.1:2080
INFO bot: Сеть: Telegram через socks5://127.0.0.1:2080 | ИИ напрямую
INFO bot: Бот запущен: @your_bot
```

### Conflict: can't use getUpdates method while webhook is active

У токена был настроен webhook (обычно остаётся от другого сервиса, где этот бот
использовался раньше). Бот теперь снимает его сам при старте
(`delete_webhook(drop_pending_updates=True)`).

Если ошибка `Conflict: terminated by other getUpdates request` — значит с этим же
токеном где-то запущен **второй экземпляр** бота. Остановите его: два процесса на
одном токене работать не могут.

## Выбор модели ИИ

ID моделей у AnyModel имеют префикс провайдера: `ag/gemini-3.7-flash-high`,
`cx/gpt-5.5`, `glm/glm-5.3` и т.д. Полный список — `check_ai.bat` (он же
записывает вывод в `check_ai_log.txt`).

В `.env` прописана `cx/gpt-5.6-sol`. Если нужна модель побыстрее и подешевле —
`ag/gemini-3.7-flash-high` или `glm/glm-5.3-flash`.

Если указанной модели у провайдера не окажется, бот при старте сам возьмёт
рабочую и напишет об этом в лог — но лучше закрепить нужную в `.env`.

## Режим консультанта по прайсу (STRICT_CATALOG)

Обычный режим бота — справочник: не нашёл ответ, спросил ИИ, запомнил.
Для прайса это не годится. Модель, не найдя цену, охотно выдумает
правдоподобную — «химчистка от 5 000 ₽» — и с `AUTOSAVE_AI=true` эта выдумка
осядет в базе и станет вашим прайсом. Дальше бот будет уверенно называть её
клиентам.

`STRICT_CATALOG=true` меняет три вещи:

1. **Модели уходит весь каталог**, а не топ-3 записи. Поэтому она складывает
   услуги, сравнивает варианты и подставляет цену для нужного класса авто.
2. **Запрет на выдумывание.** Нет в каталоге — бот говорит, что нет, и даёт
   контакт менеджера. Никаких «примерно» и «в среднем по рынку».
3. **Ответы ИИ не сохраняются** в базу. Прайс наполняет человек.

Настройка в `.env`:

```ini
STRICT_CATALOG=true
AUTOSAVE_AI=false
FALLBACK_CONTACT=Менеджер: +7 900 000-00-00
BUSINESS_INFO=детейлинг-студия: мойка, химчистка, полировка, керамика, оклейка
```

### Что бот умеет в этом режиме

Проверено на демо-прайсе из 47 записей (`price_detailing_demo.csv`):

| Вопрос клиента | Ответ |
|---|---|
| «полировка и химчистка на джипе сколько выйдет» | Джип — класс 3. Химчистка 22 000 ₽ + полировка 10 000/22 000 ₽. Итого 32 000 или 44 000 ₽ |
| «мойка и чернение шин на седане бизнес класса» | Класс 2: мойка 600 ₽ + чернение 600 ₽. Итого 1 200 ₽ |
| «у меня камри, сколько керамика» | Camry — класс 2. Полировка 18 000 ₽ + керамика 27 000 ₽ = 45 000 ₽ |
| «сколько стоит перетянуть салон в алькантару» | Такого в каталоге нет → к менеджеру |
| «сколько держится ваша керамика» | Срок в каталоге не указан → к менеджеру |
| «чем керамика отличается от воска» | Объясняет разницу, но про свои сроки и цены — только из каталога |

Границу бот держит по смыслу: объяснить, что такое керамика вообще, — можно,
это общие знания; сказать «наша керамика держится 3 года» — нельзя, если этого
нет в прайсе.

### Как наполнить прайс

Проще всего CSV: колонки `question;answer`, одна услуга — одна строка. Цены по
классам складывайте в один ответ:

```
сколько стоит полная химчистка салона;Полная химчистка салона: класс 1 — 12 000 ₽, класс 2 — 16 000 ₽, класс 3 — 22 000 ₽.
```

Обязательно добавьте запись с правилами классификации — по ней бот сам
определит класс по марке или типу кузова:

```
как определить класс автомобиля;Класс 1 — хэтчбеки, малые седаны. Класс 2 — седаны комфорт/бизнес, малые кроссоверы. Класс 3 — представительские седаны, полноразмерные кроссоверы, джипы, минивэны.
```

Готовый пример — `price_detailing_demo.csv`. Пришлите его боту файлом, и он
импортируется. Записи с пометкой ЗАМЕНИТЕ (адрес, график, контакты) поправьте
под себя через `/add`.

### Запись на осмотр: превращаем вопрос в заявку

Бот, который называет цену и замолкает, теряет клиента ровно там, где тот
готов действовать. `LEAD_CAPTURE=true` добавляет под каждый ответ кнопку
«Записаться на осмотр» и короткий диалог: имя → телефон → машина → когда
удобно. Телефон можно отдать кнопкой Telegram — без опечаток.

Записаться можно и словами: «хочу записаться», «запишите меня на завтра»,
«можно подъехать в субботу», или командой `/zapis`.

Заявка сохраняется в таблицу `leads` и **сразу уходит владельцу**:

```
🔔 Заявка №1

👤 Дмитрий — +79261072120
🚗 Toyota Camry 2019
🕒 Удобно: завтра после 18
❓ Спрашивал: у меня камри, сколько керамика

Написать в Telegram (@klient)
```

Последняя строка — то, что отличает заявку от строчки в CRM: менеджер жмёт
ссылку и пишет человеку в один клик. А «Спрашивал» показывает, с чем клиент
пришёл, — разговор начинается не с нуля.

Настройка:

```ini
LEAD_CAPTURE=true
LEAD_CHAT_ID=            # id чата студии; пусто — шлём в ADMIN_IDS
LEAD_BUTTON=📝 Записаться на осмотр
LEAD_DONE=Записал! Менеджер свяжется с вами, чтобы подтвердить время.
```

`LEAD_CHAT_ID` удобно ставить на рабочую группу студии — заявки видят все
мастера сразу. Узнать id группы: добавьте в неё `@userinfobot`.

`/leads` — последние 15 заявок и счётчик за неделю.

Проверка всего пути без Telegram: `python test_booking.py` — прогоняет диалог
с подставными объектами, включая кривой телефон и отмену посреди разговора.

### Проверка прайса на противоречия: /audit

Главная опасность прайса — не выдумки модели (их закрывает строгий режим), а
**одна и та же цена, записанная в двух местах**. Услугу легко упомянуть дважды:
в её собственной записи и «заодно» в описании смежной («перед керамикой нужна
полировка — 12 000 ₽»). Потом одну цену правят, вторую забывают, и бот начинает
называть клиентам две разные цифры — обе честно взятые из прайса.

Глазами это не ловится: записей десятки, цифры разбросаны по тексту.

```
/audit
```

```
Услуг с расходящимися ценами: 1

«Восстановительная полировка кузова»
  [21] 13 000, 18 000, 22 000   ← сколько стоит восстановительная полировка кузова
  [23] 12 000, 18 000, 22 000   ← сколько стоит керамика на кузов
```

Проверить CSV до импорта: `python audit.py price.csv`. Код возврата 1, если
что-то нашлось, — можно вставить в свой скрипт обновления прайса.

Детектор считает услуги одинаковыми, если названия существенно пересекаются
словами **и** списки цен совпадают больше чем наполовину. Одна случайно общая
цифра (у химчистки кожи и велюра совпадает 1 900) конфликтом не считается.

**Как не создавать противоречий.** Цена услуги живёт в одном месте. В смежных
записях ссылайтесь на услугу словами, а не повторяйте цифры:

```
плохо:  Керамика: 22 000 ₽. Перед ней нужна полировка: 12 000 ₽.
хорошо: Керамика: 22 000 ₽. Перед нанесением обязательна восстановительная
        полировка кузова — она оплачивается отдельно, цена в записи про полировку.
```

Бот видит весь каталог целиком, поэтому найдёт цену полировки сам и сложит:
«Керамика на хэтчбек 22 000 ₽ + полировка 13 000 ₽, итого 35 000 ₽».

### Экономия токенов: фильтр «не по теме»

В строгом режиме на каждый вопрос в контекст модели уходит весь прайс.
Значит «сколько стоит шаурма» обходится ровно столько же, сколько настоящий
вопрос про керамику. Поэтому до вызова модели стоят три бесплатные отсечки.

**Приветствия** («привет», «спасибо», «ок») — бот отвечает справкой сам.

**Фильтр по словарю каталога.** Из всех слов прайса собирается словарь
предметной области. Если ни одно смысловое слово запроса в нём не встречается,
модель не вызывается:

```
INFO bot: Не по теме, в ИИ не пошло: сколько стоит шаурма
```

Клиент получает `OFFTOPIC_REPLY` — вежливый список того, что спросить можно.

Три тонкости, без которых фильтр работает плохо:

- **Слова торга не в счёт.** «Стоит», «цена», «почём» есть в любом прайсе, и
  «сколько стоит шаурма» проходило фильтр через слово «стоит».
- **Цифры не в счёт.** «Реши уравнение 2x+5=13» проходило, потому что 13
  встречается в ценах.
- **Общие вопросы к любой компании всегда проходят.** Слова «находитесь»
  в прайсе нет, но «где вы находитесь» — законный вопрос. Адрес, часы, запись,
  оплата, гарантия, сроки учтены; своё можно дописать в `EXTRA_TOPIC_WORDS`.

Фильтр намеренно мягкий: пропустить лишний вопрос — потерять копейки, отшить
клиента — потерять клиента. Проверка — `python test_guard.py`: 20 клиентских
формулировок должны проходить, 14 посторонних отсекаться.

**Лимит на человека.** `RATE_LIMIT_PER_HOUR=20` — скользящее окно в час.
Обычному клиенту хватает с избытком, шутника останавливает. Админов не
касается.

### Сколько это стоит

`STRICT_DIRECT_MIN=0.90` означает: из базы бесплатно отвечаем только на почти
дословное совпадение, остальное идёт в модель вместе с каталогом. Каталог из
47 записей — примерно 7 КБ, около 2–3 тысяч входных токенов на запрос.
Хотите дешевле — снизьте `STRICT_DIRECT_MIN` до 0.70: чаще будет отвечать
готовой записью, но на «химчистка на кроссовере» выдаст цены по всем трём
классам вместо нужного.

Проверить поведение на своём прайсе: `python test_catalog.py` — прогоняет
список вопросов и печатает, что ответил бы бот и откуда взял ответ.

## Переезд на свой аккаунт AnyModel

Набор доступных моделей у разных аккаунтов и тарифов отличается, поэтому смена
ключа — это не только новая строка в `.env`.

1. Зарегистрируйтесь на [anymodel.org](https://anymodel.org/app/register), пополните баланс.
2. В личном кабинете создайте API-ключ.
3. Впишите его в `.env`: `AI_API_KEY=...`
4. Запустите `check_ai.bat` — он проверит ключ, покажет список доступных вам
   моделей, протестирует и основную модель, и модель переспроса, а в конце
   напечатает готовые строки для `.env`.
5. Скопируйте их в `.env` и перезапустите бота.

Возможные ответы `check_ai`:

| Код | Что значит |
|---|---|
| `401` / `403` | ключ неверный, удалён или скопирован с ошибкой |
| `402` | закончился баланс — пополните счёт |
| ошибка соединения | AnyModel не открывается: включите VPN |

Если каких-то моделей на вашем аккаунте нет, `check_ai` подберёт замену из
доступных и напечатает её ID. Бот умеет то же самое на старте, но лучше
закрепить конкретные модели в `.env` — иначе выбор может меняться от запуска
к запуску.

Ключ и токен бота независимы: меняя аккаунт AnyModel, `BOT_TOKEN` трогать не
надо, база знаний тоже остаётся на месте.

**Эмбеддинги** бот тоже подключает сам: если среди моделей провайдера найдётся
модель с `embed` в названии, при старте включится умный поиск по смыслу, а в логе
появится подсказка выполнить `/reindex` (проиндексировать уже накопленные записи).
У AnyModel таких моделей нет, поэтому по умолчанию работает переспрос.

## Смысловой поиск: переспрос вместо эмбеддингов

Поиск по словам не связывает синонимы: «вернуть **покупку**» и «как вернуть
**товар**» для него разные вопросы. Обычно это лечат эмбеддингами, но AnyModel
их не отдаёт. Вместо них бот делает так: если лучший результат попал в серую
зону, он одним коротким запросом спрашивает дешёвую модель — «какая из этих трёх
записей отвечает на вопрос, или 0?». Ответ — одна цифра, это в разы дешевле
полной генерации.

Что даёт на тестовом наборе из 22 запросов (8 записей в базе):

| | было | стало |
|---|---|---|
| верных | 16 | 22 |
| ложных срабатываний | 1 | 0 |
| промахов (ушло в ИИ зря) | 5 | 0 |

Переспросов при этом — 8 из 22 запросов, и половина из них экономит полноценный
запрос к ИИ.

Настройка порогов — командой `/find <текст>`: она показывает скоры и помечает
✅ (ответ из базы), 🤔 (серая зона, будет переспрос), ▫️ (мимо), а для серой зоны
сразу прогоняет переспрос и пишет его вердикт.
